# Implemented trust foundation and operational boundaries

25 October 2026. Read [research](research.md) and [design](design.md) together with this delivery record. A proposed target is not a measured production SLA.

## Implemented

One shared source registry validates browser and server URLs for all supported employers. The original two-employer browser allowlist defect is repaired. Twenty curated employer boards use Greenhouse/Lever; three new verified scoped boards are Canopy, Unframe and Aidoc. Jobicy's explicitly reusable public QA/Israel feed is a separate remote-candidate source, not a guarantee of Israeli eligibility. No credentials, paid wallet, partner feed, LinkedIn search or Indeed search were enabled.

Visits, reloads and refresh buttons check a shared due-source cache. Healthy ATS feeds have a 15-minute floor; Jobicy has an hourly floor and a disclosed three-hour upstream delay. Refresh cannot bypass cadence, a lease or failure backoff. Complete ATS snapshots establish removals; malformed/failed snapshots preserve prior rows. Jobicy uses sequential opaque-cursor pagination (bounded to five pages/1,000 records); exceeding the bound rejects the update without falsely closing records. Rolling-feed absence triggers explicit status batches of at most 100, never closure by disappearance. Unknown rolling statuses are withheld from active recommendations and retained as unknown in history.

`fit-v1` implements skills35/experience25/role15/work15/compensation10. Missing dimensions earn zero without redistribution. A number requires a confirmed active CV, two comparable requirement terms and at least60 evidence-weight points. Otherwise cards show insufficient information. Confidence is an uncalibrated provenance heuristic; job-data completeness and comparable input weight are separately labelled. Scores recompute from current CV/profile/preferences/job inputs; they are not stored in public rows or advertised as hire probabilities. Existing evidence-v3 terminology explanations remain available for compatibility.

Confirmed structured criteria are saved with account revision controls: skills, relevant years, current country, country-specific authorization, sponsorship, languages, qualifications, licences, clearance, salary/currency/period, employment types and timezone. Target role/district/styles remain in existing preferences. A free field is optional and stays unknown. Structured seniority, multiple target countries/authorization records and semantic experience relevance are future extensions, not shipped capabilities.

Default server filtering removes explicit blockers before signed-cursor pagination. Inspection modes expose blockers. Filters cover role, district, applicant country, known/unknown remote-country restriction, salary/currency/period, inferred title seniority, employment type, publication date, source and eligibility. Missing-value behavior is explicit. A separate checkbox includes unspecified work arrangements. Loaded-result sorting is clearly labelled; it does not claim a globally ranked database.

Cards/details expose source, location/work arrangement, compensation when supplied, fit/insufficiency, eligibility questions and timestamps. Details expose extracted requirements and short source evidence, optional skills, original link, first-seen/deadline unknowns and source references. Jobicy links warn that a provider account may be required. Employer application-page reachability is checked separately from source publication. Generic HTML200, redirects, timeouts and403 do not establish an open posting or candidate eligibility. Provider-ID presence is the source-publication check. Unknown remains unknown.

Detail opening and the first-party Apply navigation recheck evidence older than15min with bounded requests and shared per-job leases. Jobicy status uses the hourly shared ingestion policy rather than visitor-triggered status polling. A first-party Apply navigation records an anonymous30-day event containing job/time/check state only; it contains no account, IP, CV or submitted-application claim. Navigation requests may include crawlers and are not confirmed human submissions. Closed/expired records are not represented as submitted applications.

The public due-source writer is `/api/feed?refresh=1&reconcile=1&limit=1`. It needs no visitor identity because it fetches only public registry sources and writes shared public cache/check metadata. It cannot mutate private profiles or resumes. Reconciliation processes at most10 oldest unchecked/day-old application paths per shared hourly lease, with three concurrent workers, and expires only anonymous click records. At most240 paths/day can be checked through hourly runs: larger catalogues need a larger measured budget or sharding. This is a rotating daily target, not proof that every path has already been checked. Existing authenticated private-data retention controls remain separate.

## Validation and measured limits

Before/after captures use the same two actual public baseline postings, anonymous synthetic account shell, route, viewport and theme. They are under `docs/screenshots/changes/discovery-trust-{desktop|mobile}-{light|dark}/`. No real CV/profile is photographed. `profile-after.png` files show the new optional structured form; a genuine pre-edit profile screenshot was not captured, so those views are explicitly after-only.

The test suite covers explicit Italy-only remote restrictions, sponsorship unknown/conflict, clearance/authorization/deadline handling, optional vs required terms, score determinism/missing weights, registry trust, cursor consistency, rolling absence/status, complete removal, preserved outage data, profile persistence across independent sessions and Apply link routing. Existing source/identity/CV/setup/accessibility/ownership regressions remain required. Actual source and link probes are recorded separately from mocked boundary tests.

The [design](design.md) lists seven-day acceptance metrics. Initial real-source observations establish candidates and transport reachability, not measured eligible coverage, form-completion validity, ranking quality, production p95 or dollar cost. Numeric operating costs and statistically calibrated ranking remain unmeasured. Restricted integrations stay disabled until the relevant keys/permissions/agreements exist.

Publication and unattended-update verification are recorded in the publication receipt after they occur. A saved schedule proves configuration, not a completed scheduled run; manual unattended-writer readback proves writer readiness only.
