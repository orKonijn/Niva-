# Job-discovery research and current-product audit

Verified **25 October 2026**. This document separates observed capabilities, implementation decisions and integrations needing permission, credentials or agreements. Public reachability is not a blanket redistribution licence. Numeric limits not established by primary documentation are marked unknown.

## Current product: observed before implementation

The live signed-in jobs and preferences screens were accessible. The configured QA-automation/Tel Aviv case returned no results. A confirmed active CV exists, but no CV text, name or other private account content is copied into this report. Structured authorization, sponsorship, language, salary and employment-type preferences are not collected by the current form.

An anonymous public API audit at **16:11:46 UTC** fetched all four pages: **188 listings across 17 boards**. 182 have unknown work arrangement; all 188 have an empty structured `skills` array; five have only a short description. No title was classified QA automation; one quality-related title is a senior management role. These are point-in-time counts, not a claim about the whole labour market.

Code audit found a concrete coverage defect: the browser accepts only AppsFlyer/WalkMe application URLs although the server registers 17 boards. This can reject otherwise valid pages from the other boards. Work-style filtering excludes unknowns even when all three styles are selected. Detail reads return stored records without outbound-path revalidation. The current `evidence-v3` score is terminology coverage from a small bilingual dictionary, not eligibility, seniority or a weighted fit score. Sorting defaults to database IDs. First-seen time, per-link verification, compensation, restrictions and click/submission distinction are missing. Existing canonical-URL deduplication preserves tracking-normalized identity but does not establish cross-site requisition identity.

Current positives: verified-session ownership, CV review/activation, account revision control, source attribution, complete-snapshot ingestion, durable source leases/backoff, signed cursors, preserved historical saves, actual source check timestamps and visible outage states. Source visits currently force healthy upstream boards; that behavior must be constrained for providers with documented polling limits.

## Board registry and coverage boundary

Discover board identifiers from official employer career links or branded hosted boards, record the exact case-sensitive identifier, discovery URL/date, known hosts, geographic scope, permission state, polling policy and review owner. Maintain a curated registry and disabled/proposed registry; never guess an exhaustive slug list. Audit failures and revisit registry ownership/permissions quarterly. The initial production scope remains Israel-based jobs plus explicitly labelled remote candidates; a geographic search parameter is not proof that a person may work from Israel. Additional countries need provider coverage and user-confirmed eligibility, not inferred worldwide access.

## Implementation decision

Implement the audited coverage fixes, evidence-preserving schema, conservative eligibility/scoring/profile fields, source-aware polling and click-time verification first. Expand the existing curated Greenhouse registry with the relevant verified boards and enable the explicitly reusable public Jobicy source on an hourly shared cache. Do not activate restricted or agreement-dependent feeds. Deliver a phased expansion plan and measurable acceptance criteria alongside real source/application observations; no subscription, paid key or commercial agreement is assumed.
