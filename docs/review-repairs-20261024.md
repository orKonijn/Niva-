## Implementation and privacy details

Private writes capture the account epoch before processing and use atomic guarded INSERT/UPDATE. Deletion advances to a random durable epoch in the same transaction/batch as scoped deletion and account-state reset. A unique epoch makes every deletion statement conditional on the successful CAS. Resume-specific deletion also removes chat/score data possibly containing that resume, while derived versions remain separate explicit records. Quotas are separate and deletion does not reset them. Chat leases are in a separate table and token-checked on release, preventing an older completion from unlocking a newer operation. Expired rows are unreadable immediately; physical cleanup has an observable operational target and still requires a running trigger.

Client generations reject delayed responses and clear selected text/drafts/chat/retry text when privacy state changes. Cross-tab invalidation clears private state. Automatic conversation reload waits for career state readiness so deletion-in-progress cannot refill the UI from pre-commit history. File-read completion cannot start an old upload after client invalidation. Browser memory clearing cannot retract copies already sent to a provider or exported by the user.

Readable Israel-local timestamps retain exact ISO values in title attributes. Source check time and upstream update time remain distinct; no publication date is fabricated. Coverage summaries are aggregated after employer exclusions and empty states distinguish outages, missing category/district coverage, unknown style and restrictive filters. No preference is silently reset. Existing saved IDs, approvals/history, pause, exclusions and device migrations remain intact; destructive reset is only invoked on disposable test accounts or explicit account-data deletion.

The [current operational matrix/runbook](current-status.md) supersedes historical milestone text. It documents maintenance prerequisites, one-hour target, failure states, migration/backup sequence, provenance scopes and review-before-release steps. Original migration files were not rewritten.

Before any provider activation, use synthetic staging resumes and adversarial grounding/cost/cancellation cases against the chosen model and independently assessed scanner. Keep those integrations disabled until evidence supports them.
