## Required fixes

1. **Publisher context:** source registry now identifies supported IDs centrally. Detail and AppStore recovery accept LinkedIn/Indeed IDs without first loading them in the feed. Existing trusted publisher/employer host/path checks remain mandatory; malformed/unknown IDs are rejected. Browser fixtures explicitly exclude targets from the initial feed, test fresh navigation/reload and independent assistant/resume routes on desktop/mobile, both themes. Missing publisher IDs remain recoverable not-found states. Node/SQLite and D1-contract regressions retain archived access only for an owning saved job or unexpired conversation reference; anonymous/other-owner/expired references remain denied.
2. **Application limits:** authenticated owners come from the existing trusted identity adapter. Anonymous browsers receive a server-signed HttpOnly one-hour cookie; stored quota keys are HMACs, never raw identity or IP. Each visitor has 120 handoff attempts/minute. Cookie-less missing-ID probes have a separate bootstrap budget and cannot block independent valid handoffs. A separate 120/minute verification budget bounds new source checks (up to two HTTP requests per check); cached checks return before this budget. Exhaustion leaves original trusted links available with unverified status. Visitor exhaustion returns Retry-After plus accessible retry/back-to-listing guidance. Tests use synthetic identity boundaries and spoofed headers, never real session abuse. Signed cookies are a browser boundary, not proof of a unique person: clearing cookies can reset anonymous identity; shared verification is bounded independently. A sufficiently distributed flood still needs platform-level traffic protection. Old visitor quota rows are purged by maintenance after their window has aged past two minutes; if maintenance stops, stale quota rows remain until it resumes.
3. **Search:** one trim/lowercase/length normalization is used by SQL, filter/cursor keys and the browser query. Padding-only input preserves the same feed query. Empty whitespace, Hebrew, case, paging and browser reload/history are covered. The separate location filter was measured as literal case-insensitive substring matching; padded location is not equivalent and this pass deliberately preserves that existing behavior.
4. **Offices:** shared district matching accepts a primary district or any office district. Cards and preference annotations now agree with existing SQL secondary-office matching. Disposable primary/secondary/multiple/unknown/negative cases cover SQL totals; rendered tests cover card count, displayed total, reload/history, and the accessible map office list. The extra map scenario uses an on-site version of the synthetic listing; map tiles are aborted, so this validates the local fallback/markers rather than remote tile delivery. The old preference test expected a secondary-office job to disappear; its explicit expected result now includes that job while retaining category/style/exclusion checks.
5. **Retention:** existing cleanup-first behavior is preserved. New local tests on both adapters deny expired reads before physical deletion, simulate two invocations less than 60 minutes apart with provider503 responses, verify deletion and cleared active pointers, expose cleanup storage failure, recover on retry, and show source-only refresh does not delete private records. These are simulated cycles, not hosted schedule evidence. See the operational dependency and staging procedure below.
6. **Copy/docs:** FAQ, terms/privacy, README and current documentation now distinguish selected global sources, Jobicy, partial daily JSearch samples, local file extraction and disabled server services. Historical receipts/milestone text remain labelled and preserved. No licensing, partnership or compliance approval is asserted. Optional mobile/filter/taxonomy/application-stage product ideas were not implemented.
