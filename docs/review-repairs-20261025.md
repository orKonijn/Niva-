## Preserved invariants and design choices

- Account deletion still advances a durable epoch in the same transaction/batch as private/state deletion; old asynchronous writes reject. The new erasure token changes only on whole-account erasure. Scoped deletion advances the write epoch and reconciles surviving rows without pretending all local drafts were erased.
- There is still one authoritative active pointer; confirmation edits do not rewrite it. Token-owned chat leases remain separate from deleted private records and release only their own token. Existing rollback, stale revision and delayed-operation regressions remain in the server suite.
- Canonical job identity, saved representative totals, persisted reference versions/check times and changed/closed states are unchanged. Tailoring still returns the exact source text/order and separate highlights; no paragraph reassociation was introduced.
- Guest Web Locks, account document revision conflicts, source attribution, unknown district/style behavior, explicit demo approvals and no employer auto-submission remain intact.
- Snapshot reads combine owner epoch/erasure, active pointer and unexpired resume rows in one SQL statement. Private original binary data is excluded. Background refresh reconciles records rather than resetting unrelated draft fields. A paired API/schema upgrade is required before relying on the new cross-session erasure protocol.
- Middleware and API payloads remain private/no-store and owner-derived. Operator health uses a separate server bearer secret. Private-Sites unattended access uses `OAI-Sites-Authorization`, distinct from the application's `Authorization` bearer; credentials are never generated, stored in source or transmitted in this pass. Watchdog sends no account/resume data and never forwards its Site service credential to the alert receiver; the staging checker never sends it to alternate origins.
- Watchdog separates a20-minute ingestion-run heartbeat bound from native schedule observation, so successful manual/external runs are not falsely reported as missed native jobs or proof of a real scheduler. It must run on infrastructure independent of the app scheduler. It cannot notify while its own host is offline without a separate monitor. Successful same-reason deliveries cool down for one hour; failed deliveries are not acknowledged and retry on the next invocation. Real operator receipt is a release gate.
